Spoon Studio / Radio Mate Bot
요구사항 분석 및 브레인스토밍

신청곡, 청취자 참여 게임, 자동 안내, 음성메시지를 한곳에서 관리하는 라디오 방송 도우미입니다. 운영 도구의 복잡함을 줄이고, 다시 방문하고 싶은 감성적인 화면을 목표로 합니다.

01. 프로젝트 개요와 범위

DJ는 방송에 집중하고,
반복되는 운영은 도구가 돕도록.

항목분석
프로젝트명Spoon Studio (저장소: radio-mate-bot)
문제 가설신청곡·게임 보상·안내를 수동 처리하면 방송 흐름이 끊기고 중복 정산이나 누락 가능성이 생긴다. 실제 사용자 인터뷰로 검증해야 하는 가설이다.
대상소규모 라디오 방송 DJ와 채팅에 참여하는 청취자
제공 가치방송별 데이터 분리, 자동 응답, 참여 보상 관리, 직관적인 대시보드
현재 기술Node.js 24+ · JavaScript ES modules · SQLite · HTML/CSS · OAuth/SSE 연동 코드
실행 형태Node 서버와 브라우저 화면. 로컬 연습 가능 / 실제 운영에는 상시 서버와 영구 저장소 필요

포함 범위

대시보드, 프로필·출석·랭킹, 게임·상점·킵, 신청곡, 자동 안내, 음성 접수, 설정 백업, 명령어 테스트, 화면 디자인

향후 검토 범위

공개 서비스 가입·탈퇴, 보관기간 자동 삭제, 전체 DB 자동 백업, 대규모 다중 인스턴스, 전송 outbox

스푼 공식 서비스가 아니라 연동을 위한 별도 도구입니다. 실제 계정 연결·방송 송신은 이번 로컬 검증에 포함되지 않습니다.

02. 브레인스토밍과 우선순위

아이디어 축문제 / 기회채택 방향
방송 준비설정 메뉴가 많아 시작 지점을 찾기 어렵다첫 화면에 테스트 진입과 스푼 연결 버튼, 대시보드에 운영 체크와 빠른 이동
참여 유도청취자가 남길 수 있는 상호작용이 한정된다출석·퀴즈·낚시·룰렛·신청곡을 기존 명령어 흐름으로 제공
감성 경험관리 화면이 기능 위주로만 느껴질 수 있다딸기우유빛 배경·리본 라디오·둥근 카드·편지함 표현
운영 신뢰동일 이벤트가 반복 도착할 수 있다event ID 중복 방지·트랜잭션·설정 버전 충돌 보호
재방문 동기성장이 눈에 보이지 않으면 동기가 약하다EXP 팬랭킹·레벨 진행·도감·킵 표시
확장 아이디어서비스 운영에 개인정보 정책이 필요하다정책 확정과 실방송 검증을 후속 일정으로 분리

MoSCoW 분류

우선순위범위
Must방송별 데이터 격리, 권한 확인, 로컬 테스트 구분, 보상 일관성, 읽기 쉬운 화면
Should신청곡 관리·자동 안내·음성 접수·반응형·설정 백업
Could테마 선택, 고급 통계, 전체 목록 채팅 페이지 넘김 (제안 / 미구현)
Won’t 이번 범위실제 결제·할인 실행, 음원 다운로드, 다중 인스턴스 운영, 자동 강퇴

브레인스토밍은 코드·README와 사용자 디자인 요청을 토대로 재구성했습니다. 설문이나 인터뷰를 수행했다는 의미는 아닙니다.

03. 사용자와 이용 흐름

DJ / 주 운영자

방송 전 게임과 안내를 설정하고, 방송 중 신청곡·보상·음성메시지를 확인합니다. 저장 여부와 실제 연결 상태를 명확하게 알아야 합니다.

청취자 / 참여자

채팅 명령으로 출석·게임·신청곡에 참여하고, DJ가 연 별도 링크에서 음성을 보냅니다. 내부 관리 API에는 접근하지 않습니다.

처음 사용하는 DJ의 여정

01 발견
첫 화면에서 어떤 도구인지 확인 → 연습 화면으로 진입
02 이해
명령어 안내 → 프로필 생성 → 대기시간 확인 → 출석 / 신청곡 테스트
03 준비
게임 설정·공지 작성 → 변경사항 저장 → 운영 체크 확인
04 연결 및 운영
개발자 앱 준비와 OAuth 동의 → 방송 연결 검증 → 실제 운영 (후속 실환경 검증)

화면 구조

첫 화면 → 방송 대시보드 → 게임 / 상점 / 신청곡 / 청취자 / 공지 / 기록 / 자동채팅 / 음성메시지 / 운영·백업 / 테스트 / 안내

청취자 음성 링크는 독립 접수 화면입니다. 입력 닉네임을 스푼 계정 인증으로 표시하지 않습니다.

  • 구름 위 리본 라디오를 첫 화면·대시보드·음성 화면에 일관되게 사용합니다.
  • 배경에는 옅은 분홍·라일락 그라데이션과 작은 도트만 두어 내용과 장식을 구분합니다.
  • 빈 목록에는 작은 편지 일러스트와 다음 행동을 알려주는 문장을 제공합니다.
  • 변경사항 저장, 권한, 접수 중지, 연결 상태는 장식보다 선명한 문구로 전달합니다.
  • 키보드 포커스와 동작 줄이기 설정을 지원하며, 모바일 표는 내부 스크롤을 사용합니다.

05. 위험요소와 검증 계획

위험현재 대응후속 검증
실제 방송 연결 실패OAuth/SSE·토큰 갱신 코드 존재개발자 앱 승인, DJ 동의, 방송 시작/종료와 실제 송신 점검
보상 중복 / 정수 초과이벤트 중복키·트랜잭션·안전 정수 검사실제 이벤트 재전달·장시간 운영 로그 확인
설정 덮어쓰기expectedRevision 충돌 시 409동시 브라우저 운영 시나리오 유지
음성 개인정보수신함 인증·링크 중지/교체·파일 용량 제한보관기간·삭제 정책·개인정보 안내 확정
백업 오해설정 백업과 전체 데이터 백업 구분서버 종료 후 data 및 암호키 보관·복원 연습
감성 디자인의 과밀장식은 이미지·배경 중심, 주요 동작에 색 집중작은 화면과 실제 사용자 평가
확장 한계단일 프로세스·SQLite 소규모 운영 전제다중 인스턴스는 워커 잠금·중앙 DB 설계 필요
