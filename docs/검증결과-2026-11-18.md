## 공식 API와 실행 환경의 한계

- [Spoon 공식 API 목록](https://developers.spooncast.net/docs/en/api-reference/endpoints)은 앱 내부 녹음창·충전창 실행, 방송 음악 송출, 이메일 조회, DJ 동의 없는 방송 입장 기능을 제공하지 않는다.
- `!보이스카드`는 공용 HTTPS 녹음 페이지를 안내한다. 스푼 앱 방송 화면 안에서 명령만으로 녹음 UI를 자동 실행하는 기능은 구현하지 않았다.
- `!스푼`은 `/스푼` 입력 방법·공식 충전 링크·조건 확인 안내를 제공한다. 사용자 기기의 결제창을 자동으로 열거나 할인 금액을 보장하지 않는다.
- `!라디오메이트`·`!봇호출`은 상태·연결 방법 안내다. 새 DJ는 공용 화면에서 OAuth 동의가 필요하다. 연결되지 않은 방송의 채팅은 봇이 수신할 수 없다.
- 조회·선택·재생 요청·멈춤 상태는 PC 관리 화면 없이 서버에서 처리한다. 실제 음악 소리는 휴대폰·태블릿·PC 중 한 기기의 `/player` 화면에서 재생해야 한다. 기기 없이 스푼 방송에 YouTube 음원을 주입하는 기능은 아니다. 외부 YouTube 앱의 재생을 봇이 제어하지도 않는다.
- 기존 공용 HTTPS로 다른 PC·모바일에서 접속할 수 있다. `localhost` 자체가 다른 PC를 가리키도록 바꾸지는 않는다. 현재 임시 서비스는 호스트 PC·서버·터널 실행에 의존하며 PC를 끄면 사용할 수 없다. 상시 클라우드 운영과 실제 모든 기기 동작 검증은 완료하지 않았다.

운영자의 실제 청취자 잔액을 임의로 지급·회수하거나 삭제하여 테스트하지 않았다. 명령 검증은 테스트 데이터에서 수행했다. 기존 운영 규칙 변경 전 설정 백업을 생성하며 사용자 퀴즈 문제를 덮어쓰지 않는다.

운영 반영 후 공용 HTTPS `/health` 정상 응답, DB `quick_check=ok`, 적용 전 백업 대비 기존 EXP·PT·복권 잔액 차이 0건을 확인했다. 사용자가 DJ 계정으로 로그인한 뒤 OAuth 연결을 이어서 완료했다. 실제 Edge 관리 화면의 방송 연결됨 상태와 활성 로그인 세션 1건의 암호화 저장을 확인했다. 현재 방송을 중단하는 실제 운영 서버 재시작 실험은 수행하지 않았다.
